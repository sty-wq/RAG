# 第一题：从段落审核到SFT样本

日期：2026-11-07。139题审核表第1题，qid `1909.00786-q01`，原403题清单序号7。
本次只制作审核建议和数据示例，没有训练，没有调用外部模型，也没有修改原CSV、题库或历史结果。所有标签仍待用户确认。

## 1. 先弄清题目在问什么

原问题：How large is the benefit of editing-based SQL query generation compared with generating entire SQL from scratch for cross-domain context-dependent questions?

通俗理解：对于跨领域、多轮上下文中的SQL生成，编辑之前的SQL，相比重新生成整条SQL，效果提升多少？

原参考答案：question match accuracy提升7%，interaction match accuracy提升11%。两项指标必须分开，不能相加。这里保留原文百分号措辞；语料表格内容缺失，不在本例中擅自把论文中的所有百分号换成统一的相对增幅或百分点。

判断时依次问：①是不是在讲本题的方法和任务？②是不是在回答“提升多少”？③比较对象和条件是否匹配？④证据是否真的出现在当前候选块里？

`yes`表示当前块直接支持答案或必要的答案部分；`no`表示不能支持本题所需结论，不代表文字错误；`uncertain`表示辅助作用或比较条件尚需确认，先不用于训练。

原问题没有明确写出BERT配置和具体基线。摘要D2说明比较对象是从零生成的SOTA基线，D5报告7%/11%，D20进一步说明带/不带BERT的收益差异。D24讨论的是更细的query-attention消融。示范保留原问题，不把不同条件的数字一概标错，也不偷偷修改基准问题。

## 6. 整理为SFT示例

本例选10条：正例D5、D20；负例D4、D8、D14、D6、D13、D34、D40、D12。覆盖高排位的主题干扰、错误数据集、其他方法与容易识别的无关内容。没有把44条负例全塞进这个小示例，也没有把4条待确认项用于训练。2:8只是演示采样，并非最佳训练比例。

每条训练记录都是：原问题 + 一条候选（原标题路径与原文） → `yes`或`no`。

`SFT示例_10条_含溯源.jsonl`保留qid、chunk_id、原排名、原文、理由、建议标签和待审核状态，便于人查看。

`SFT示例_10条_prompt_completion.jsonl`只有prompt和completion两个字段；与含溯源文件逐行对应。输入逐字复用当前本地score.py的指令、系统前缀、问题/文档格式和assistant后缀，没有把参考答案、审核理由、原排名或标签放进输入。模型目标只输出yes/no，不是生成“7%和11%”。

语义上的简化展示（不是文件内实际完整prompt）：

```json
{"query":"原问题全文","document":"D5原标题路径和原段落全文","completion":"yes"}
{"query":"原问题全文","document":"D8原标题路径和原段落全文","completion":"no"}
```

实际JSONL没有这些占位文本，全部是保存的完整问题和完整候选段落。

## 7. 正式训练前还需要确认什么

1. 用户确认标签，尤其是D2/D24/D31/D35的边界；本例未修改CSV中的人工审核字段。
2. 统一所有题的“直接答案/辅助证据”标注政策。不能只用是否匹配原gold判正负。
3. 按论文隔离训练、验证和测试；检查候选来源论文的交叉泄漏。当前全部标记demo_unassigned，不是已划分的训练集。用本题训练后，本题也不能再作为未见测试题证明泛化。
4. 训练器只在yes/no目标上计算损失，并核验token边界、截断、EOS和padding处理；不能对已经含特殊token的prompt再次套聊天模板。本次只验证字符串模板和数据，没有运行tokenizer或训练器，未宣称可直接套任意框架运行。
5. 单独保留Dense原本做对的样本作回归检查，并混入其他训练题中的正常样本。只训练这一题不能保证“以后不退化”。
